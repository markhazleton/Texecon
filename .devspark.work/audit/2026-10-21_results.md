#### ARCH1 — Route-shape logic implemented in three places (HIGH)

**Intent**: Principle III requires that sitemap, static pages, and React SEO output agree *exactly* on URL shape. Today that is true only because three hand-written copies happen to agree.

```js
// scripts/generate-static-pages.js:24
function withTrailingSlash(url) {
  if (!url || url === '/') return '/';
  return url.endsWith('/') ? url : `${url}/`;
}
/** Build a menu hierarchy (mirrors menu-utils.ts buildMenuHierarchy). */
```

```js
// scripts/generate-sitemap.js:26
function generateSEOPath(item) {
  const url = item.url || '/';
  if (url === '/') return '/';
  return url.endsWith('/') ? url : `${url}/`;
}
```

```ts
// client/src/lib/seo-utils.ts:13
function withTrailingSlash(url: string): string { … }
```

The copies already differ slightly: `generateSEOPath` handles `''` differently from the other two. The comment "mirrors menu-utils.ts buildMenuHierarchy" also shows that menu derivation (Principle II) is kept in sync by hand. Only the TypeScript copy has tests (`seo-utils.test.ts`), so a change to one JS copy would pass every gate and still ship mismatched canonical URLs and sitemap entries.

**Recommendation**: Extract one dependency-free module for route normalization and menu hierarchy. A plain `.js` file with JSDoc types, or a `.ts` file compiled for scripts, would work. Import it from `generate-sitemap.js`, `generate-static-pages.js`, `seo-utils.ts`, and `menu-utils.ts`, and give that module the existing trailing-slash tests.

#### TYPE1 — Generator emits `any` (MEDIUM)

Principle V: "`any` MUST NOT be introduced unless unavoidable and justified in code review."

```js
// scripts/fetch-content.js:290-295 (emits client/src/data/content-types.ts:45-50)
  pages: {
    home: any;
    about: any;
    analysis: any[];
    all: any[];
  };
```

**Intent**: Principle V says most failures in this repo are mismatches between content and routes. `pages` is the exact payload that routes and SEO are built from, so it is the place where typing matters most.

**Recommendation**: In the generator, emit the content-item interface that already exists in the generated file (or `unknown` plus a narrowing helper), and use it for `home`, `about`, `analysis[]` and `all[]`. Fix the generator, not the generated file (Principle IV).
